The printer writes the form

printmax asks each printer for its Get-Printer-Attributes and builds the option editor from the answer. Paper sizes, trays, duplex and finishing are the ones that device actually has, and every job is validated against them before it is sent.

Capabilities are fetched again each day and diffed, so a changed tray or a dropped option is flagged instead of quietly breaking a preset.

{
  "name": "Sunday bulletin",
  "description": "A4, double-sided on the long edge",
  "scope": "global",
  "options": {
    "media": "iso_a4_210x297mm",
    "sides": "two-sided-long-edge",
    "print-color-mode": "monochrome",
    "copies": 40
  }
}

Ask the printer first

Check a preset with an IPP Validate-Job. The device itself confirms it would accept the options, and nothing is printed.

Validate-Job → successful-ok

No spooler to babysit

When the printer is unreachable, jobs retry with backoff. When it is busy with someone else's job, they wait it out. Real rejections show the printer's own status and message, not a generic failure.

Booklets, folds and staples the IPP attributes never mention

Some finishing only exists as private PostScript in a vendor's driver. Upload the printer's PPD, switch it to PostScript via PPD, and printmax sends the job the way that driver does: Ghostscript output wrapped in the PPD's own PJL and setup snippets, in *OrderDependency order. It is opt-in per printer, and plain IPP stays the default.

% from the Toshiba e-STUDIO PPD, emitted into the job's setup block
*Folding True/On: "<</TSBPrivate (DSSC PRINT FOLD=CENTER) >> setpagedevice"
*Stapling SS/Saddle Stitch: "<</TSBPrivate (DSSC PRINT STAPLING=1028) >> setpagedevice"

% in printmax they sit in the same flat option map as everything else
{ "ppd:Folding": "True", "ppd:Stapling": "SS", "copies": 120 }

Install

curl -O https://raw.githubusercontent.com/bevanjkay/printmax/main/docker-compose.yml
docker compose up -d

Open port 8080 and create the admin account with the setup token printed in the container log. Then add a printer by its IPP URI, usually ipp://<host>/ipp/print, or scan the network for one.

Every setting has a default. The README covers the rest: reverse proxies, printer certificates and network discovery.

Why there is no CUPS

Modern network printers already speak IPP. Talking to them directly means the options you see are the printer's own, rejections arrive in its own words, and there is no second print system in a container to keep alive.
